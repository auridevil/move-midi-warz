# RD-14 · Hands-on guide, by use case — review state

The spec is `orbit2/docs/redesign/DECISION.md` (§3 the RD-14 row, added by the conductor 2026-11-23). Panel per the REVIEW-PANEL table: the three core reviewers plus maya, rio and noor. Built in three commits: the guide text (`docs/GUIDE.md`), the guide in the app (`tools/build-guide.mjs`, the "?" dialog's third tab, ⌘K), and the tests and browser check.

## What shipped (for the panel)

- **`orbit2/docs/GUIDE.md`** (type guide): "first five minutes" (12 lines) and ten use cases, each with goal, what you need, a two-column table **Mouse & keys | Move**, "if it doesn't" (two slips) and "go further" (one link). Written by the Tess persona from a live drive of the page; bold is reserved for exact control names (left) and Move table row names (right).
- **`orbit2/tools/build-guide.mjs`**: generates the HTML block of the guide tab between `<!-- GUIDE:BEGIN -->` and `<!-- GUIDE:END -->` in `index.html` (no runtime markdown parser, no dependency); sections are `<details class="guide-case" id="guide-<slug>">`; `(show me: <quest title>)` becomes a "show me" button on the quest's own ghost gesture (`showMe(quest)`). Run `node orbit2/tools/build-guide.mjs` after editing the guide.
- **The tab**: `htab-guide` / `hpane-guide` in the "?" dialog, same pattern as keys & Move (`HELP_TABS`, arrow keys, `openHelp('guide', sectionId)`). Links inside the guide open and scroll to a section inside the dialog; the dialog scrolls, the page never does.
- **⌘K**: every section is an entry (`find.js` `GUIDE_HOW` = a "how do I …" phrase per section, `entry({ weak: true })` so a guide case never outranks a real control of the same word: "stems" is the export, "how do i chop a break" is the guide). Enter closes the sheet find opened and opens "?" on that section.
- **No control added to the main screen** (A5): the guide lives inside the dialog; face audit counts are unchanged.
